# SessionDeck 产品需求文档

> 把 Claude Code、Codex、DeepSeek Harness 的具体会话变成联系人卡片：在外面看状态，点进去继续原生交互，需要协作时再组成群组。

- 版本：v0.2.0
- 日期：2026-09-29
- 产品形态：本地优先的 Web 应用
- 当前目标：完成会话联系人、原生交互和 Fork，并实现基础群组闭环
- 价值判断：以日常使用是否顺手为准，不以商业化为目标

## 1. 产品定义与优先级

SessionDeck 管理的是**一个个具体会话**。同一个后端可以有多个联系人，例如三个 Codex 会话分别负责实现、审查和实验。联系人不是模型，也不是一个固定的 Agent 人格。

核心体验：

1. 打开网页，看到自己各个后端的会话联系人卡片。
2. 不进入会话，就能辨认它正在运行、等待自己处理、出现异常，或状态尚不确定。
3. 点击卡片，进入该会话，继续输入、纠正方向或处理原生审批。
4. 为卡片改名，或把已有上下文 Fork 成另一个独立联系人。
5. 后续在群组中组织共同任务：新建成员，或将已有会话 Fork 入群；随时单独进入成员会话纠正。

优先顺序：**会话卡片与进入会话 → Fork → 基础群组**。本轮交付覆盖三个阶段；群组不能挤占卡片体验，也不能只留下空壳入口。

## 1.1 现成工具与是否值得做

已有工具覆盖了多会话管理、终端复用和 Agent 协作等相邻需求。选型要同时检查三个条件：**跨 Claude Code、Codex、DeepSeek Harness 的具体会话联系人卡片、可点击回到原生会话、由用户主导的跨后端群组**。支持多个模型或多个终端，并不自动满足这三个条件。

| 工具形态 | 已经解决的事情 | 与本项目需求的差距 |
|---|---|---|
| 各后端自己的 CLI / Web / app-server | 原生登录、审批、历史、Fork 和会话交互 | 各自独立，不能提供统一联系人、跨后端状态和群组入口 |
| tmux、Zellij、终端标签页 | 同时挂起多个终端，切换很快 | 只管理终端窗口，不知道原生会话身份、提醒或群组消息关系 |
| VS Code / IDE 插件 | 在编辑器中使用某一个 Agent，复用部分原生能力 | 通常绑定单一后端或工作区，不能可靠承载三种后端的精确会话与跨会话 Fork 关系；插件也不能直接当作 Web UI 嵌入 |
| Claude Squad、Conductor 等多 Agent 工作区 | 并行管理编码任务，有的结合 Git worktree | 还需逐项核实 DeepSeek Harness 原生接入、精确会话状态、上下文 Fork 和用户主导的群组路由 |
| OpenHands、ChatDev 等 Agent 工作台 | 提供统一聊天或自动协作界面 | 往往重新实现 Agent 交互，不能直接复用用户已有 CLI 的登录、审批和原生上下文 |

SessionDeck 的价值是减少个人开发者在多个原生会话之间切换的认知和操作成本。只要卡片状态可信、点击不串会话、Fork 不丢上下文、群组投递可追踪，它就有明确的日常价值。首版坚持本地优先、用户确认投递和原生能力复用，控制开发量并验证这个核心假设；如果现成工具已经能完整满足这些工作流，也优先采用现成工具。

## 2. 复用原则

- 优先复用后端自己的 CLI、认证、权限确认、恢复和 Fork 能力。
- Codex 通过原生 app-server 提供可交互的「图形对话」，也可切换到同一会话的原生终端；认证、模型、工具执行和权限决定仍由 Codex 处理。Claude Code 保留只读「对话记录 / 原生终端」，dsh 复用自己的 Web 界面。
- 保留后端原生交互习惯。SessionDeck 提供联系人、状态、入口和群组组织。
- 能通过受支持的原生接口完成的工作，不读取内部数据库后自行模拟。
- 不假定 VS Code 插件能够直接嵌入网页。只有接口、运行环境和许可证合适时才复用其实现。
- 后端不具备或尚未验证的能力，明确标注不可用及原因；不能用看起来成功的假操作代替。

## 3. 用户与工作流

面向同时使用 Claude Code、Codex、DeepSeek Harness（下称 dsh）的个人开发者。这里的“跨平台”首先指跨这三种 Agent 后端；首版无需同时交付桌面应用、移动应用和多操作系统安装包。

典型工作流：创建“登录实现”Codex 联系人 → 图形对话中布置任务 → 返回卡片查看状态 → 提醒后点击原会话处理 → Fork 出“登录方案实验” → 建立“登录功能”群组 → 在群内新建 Claude 设计成员、dsh 验证成员，或 Fork 已有联系人入群 → 分别派发任务、纠正成员、共享结果。

## 4. 会话联系人

### 4.1 卡片内容

| 字段 | 展示要求 |
|---|---|
| 名称 | 用户可随时修改，持久化保存 |
| 后端 | Claude Code / Codex / DeepSeek Harness |
| 状态 | 清晰徽章；未知或推断状态可辨认 |
| 最近活动 | 时间及适合显示的简短说明 |
| 提醒 | 等待输入、审批、异常等需要关注的信息 |
| 工作目录 | 帮助区分项目，可缩略显示；旁边的复制按钮一键复制完整路径，不打开会话 |
| 最近输入 | 显示原生历史中最近一条真实用户输入的简短摘录，最多 240 字符、卡片最多两行；无可读历史时省略 |
| 关系 | 可识别群组归属及 Fork 来源 |

默认视图优先显示置顶及最近活动的会话。支持名称、目录和最近输入摘录搜索、后端及状态筛选、按活动／名称／创建时间排序、归档与查看归档。筛选按页面保留；复杂标签、全文检索、成本统计和多套布局不属于首版必要条件。

最近输入与状态分别展示，不把工具结果、终端控制字符或系统指令当成用户任务。摘录保存在本地联系人元数据中，不调用模型生成摘要；刷新摘录不会增加未读提醒或改变最近活动时间。运行会话约每 5 秒、非运行会话约每分钟读取一次，分批限制并发；历史尚未落盘、很多联系人或文件索引尚未刷新时会有延迟。待初始化的 Fork 不冒用来源会话的记录。

### 4.2 卡片操作

- **新建**：选择后端、名称、工作目录，创建可交互会话。
- **进入**：打开同一个会话；重开详情不得无声创建新上下文。
- **改名**：只需改变本工具中的显示名称，不要求后端也支持重命名。
- **Fork**：调用后端原生分叉，产生新联系人并记录来源。
- **归档**：收起联系人并保留信息；运行中的进程如何处理必须明确。
- **恢复 / 停止**：按后端和进程实际能力展示；停止不是删除历史。

新建或恢复会话前检查原生程序是否存在，并显示可操作的失败原因。登录与模型使用额度沿用用户自己的后端配置。dsh 的 Web 服务按需启动，会话入口仍然指向具体的原生会话。

在群组中新建成员时，默认沿用该群组最近活跃成员的工作目录；也可显式选择最近使用的目录，或填写其他已有目录。切换后端不会覆盖已填写的路径。本工具不会因为选了一个目录就新建工作区或 Git worktree。

新建联系人、群内新成员及 Claude/Codex Fork 的目录字段均支持「浏览」：弹出网页内目录资源管理器，可逐层进入、返回上一级、回到主目录、显示隐藏目录、筛选文件夹并选择当前目录。也可粘贴绝对路径、带引号的路径、`~/` 路径或 `file://` 目录链接，中文与空格按实际路径处理。只列出目录，不上传项目文件。

目录属于**运行 SessionDeck / Agent 的电脑**；从另一台电脑访问时同样如此。这里使用网页弹窗而非操作系统原生文件选择器，因为浏览器通常不会提供可交给本机 CLI 的绝对路径。不存在、无权限或粘贴了网页 URL 时显示错误并保留表单。

### 4.3 会话身份与接入范围

SessionDeck 的 `id` 用于卡片和群组关系；`nativeSessionId` 指向后端真正的会话，两者不得混淆。某些后端只有启动并产生事件后才能获得原生 ID；此时显示“尚未识别”，不能拿卡片 ID 冒充。

卡片创建并启动后即可精确进入其托管进程。支持原生 app-server 的 Codex 版本在创建时即取得真实线程 ID，Fork 也直接返回独立子会话 ID；原生终端连接到同一线程。旧版本使用兼容终端路径，通过完成通知确认原生 ID，确认前不能 Fork。工具不凭“相同目录、相近时间”猜测会话身份。

首版优先可靠管理 **SessionDeck 自己启动或通过原生 ID 恢复的会话**。支持显式发现并导入本机历史会话；发现磁盘中的历史会话，不等于能接管另一个终端中正在运行的进程。

外部历史接入必须使用后端原生恢复能力。任意现有终端进程的接管、所有历史的自动导入、跨设备同步均可后置。已有联系人的只读记录使用有界索引定位文件，只读取该联系人精确原生 ID 对应的内容。

## 5. 状态与提醒

### 5.1 状态语义

| 状态 | 含义 |
|---|---|
| 运行中 | 有可信依据表明后端正在处理工作 |
| 等待输入 | 后端正在等待用户补充内容 |
| 等待审批 | 后端在等待用户批准操作 |
| 空闲 | 当前可继续交互；不代表用户任务已验收 |
| 已停止 | 托管进程结束，保留卡片与历史 |
| 异常 | 启动失败、进程错误或明确后端错误 |
| 未知 / 连接中断 | 缺乏可靠依据或失去连接 |

归档是联系人生命周期属性，不混入执行状态。后端结束一轮输出，不自动代表任务完成；任务完成和结果验收另行记录。

### 5.2 可信度要求

状态同时记录来源、解释和更新时间：

- **原生**：来自受支持的结构化事件或可验证的进程生命周期。
- **推断**：来自终端提示或输出特征；界面标明推断，允许进入核对。
- **未知**：没有足够依据；不杜撰进度和完成状态。

仅凭一段时间没有输出，不能认定 Agent 已完成、阻塞或等待审批。用户普通文本中出现“approve”等词语也不应直接触发确定性审批提醒。

卡片通过实时事件更新，关键状态变化产生站内提醒。浏览器系统通知可由用户主动启用；未授权系统通知时站内提醒仍能使用。刷新网页后保留会话，不把历史消息重复当作新提醒。

## 6. 私聊路径：Web 中使用原生会话

Codex 默认使用可交互的「图形对话」：用户在网页输入任务，回复实时流入，并渲染 Markdown、列表、表格和带语法高亮的代码块；代码可一键复制。命令、文件修改和工具输出以可展开卡片展示，执行计划单独展示。图形对话目前仍以文本任务为主；图片可在「原生终端」中通过剪贴板或工具栏选择按钮接入，SessionDeck 会把图片保存在本机数据目录并将带引号的路径预填到 Codex 原生输入，用户确认看到 `[Image #1]` 后自行按回车发送。支持 PNG、JPEG、GIF、WebP，单张不超过 10 MiB；上传不会自动提交，也不会在审批等待时插入输入。Claude、dsh 和图形对话本身暂不提供统一附件上传，IDE 文件编辑器和完整 Diff 编辑器也不在本轮范围。

交互通过 [Codex app-server](https://developers.openai.com/codex/app-server/) 的原生线程、事件、审批和中断协议实现，这是 Codex IDE 扩展使用的服务能力。复用用户安装的 Codex 和现有配置，不另建模型调用链，也不直接嵌入 VS Code 插件。

原生命令／文件／权限审批显示操作详情和原生可选决定；用户明确选择后才答复。原生提问显示选项及协议允许的补充输入。不支持的请求明确提示转到原生终端处理。断线或已由其他界面处理的请求不能继续使用过期审批。

输入框的「停止生成」只中断当前一轮，随后仍可继续聊天；详情顶部的「停止会话」结束该联系人的托管连接和终端。图形模式创建／恢复不启动 TUI，切换到「原生终端」时连接同一个原生线程；切回图形模式不会重启会话。切换卡片、刷新或读取历史不会自动提交消息或启动 Agent。

草稿和待确认的发送标识保存在当前标签页的浏览器存储中，刷新、关闭详情再打开时恢复。服务端先持久化发送标识，再交给 Codex；同一标识不重复执行。响应丢失时显示「发送结果待确认」，先查询结果，仍未知则由用户核对原生历史后确认，禁止自动重发。服务重启也保留待确认记录；数据库仅保存发送标识、文本摘要哈希及结果，不额外保存私聊正文。

Claude Code 仍通过网页原生终端输入和审批，也可切换只读「对话记录」回看；dsh 使用自己的原生 Web 会话，内嵌受限时可在新标签页打开同一个会话。视图偏好按后端保存在当前浏览器；未检测到图形聊天能力的旧 Codex 或旧版 SessionDeck 服务继续使用记录／终端路径。

记录和图形对话都绑定精确原生 ID，支持滚动回看和选中文本共享。Codex 图形流保留最近 200 个消息／工具条目，总文本与单条内容都有上限，截断时提示完整历史仍在原生会话中。未启动会话先只读原生保存的历史，恢复后接入结构化事件；只读历史不启动原生服务。Markdown 不执行原始 HTML、脚本链接或自动加载远程图片。

必要行为：

- 卡片点击后进入对应会话。终端支持键盘输入、粘贴、滚动和尺寸变化；dsh 保留自己的聊天与操作界面。
- 切换卡片或关闭详情不会终止会话；再次进入仍是同一个原生会话。
- 每个会话有可复制、可收藏的网页链接。刷新和浏览器前进／后退恢复相同视图，不自动启动 Agent 或提交任务。
- 终端连接短暂中断能够重连；应有可见的连接状态和合理的输出回放。
- Codex 图形审批仅转发原生请求和用户的明确决定；其他后端在各自原生界面处理审批。
- 服务重启会丢失其托管的活进程时，必须显示真实状态；有原生 ID 的会话通过后端恢复命令继续。
- 单个终端停止和服务关闭都会等待原生进程完成回收；停止期间拒绝输入和重启，清理失败仍保留停止屏障。服务收到关闭信号时，会等待自己启动的原生进程和终端树完成回收，再释放数据目录锁；因此重启不会与上一代托管进程并行。原生工具主动脱离的外部任务不在 SessionDeck 的回收范围内。
- 输入只发送至当前选中的会话。多个终端并存时不得串线。
- dsh 的停止操作通过原生接口取消该成员的任务，不应关闭共享 Web 服务或影响其他成员。恢复后尚未附着原生页面的空闲会话没有活动任务，停止按幂等操作处理；事件流暂时无法确认执行状态时显示“未知”。

本轮先完成 Codex 图形交互；Claude 图形输入与审批、跨后端统一 Diff 和 IDE 能力后置。

## 7. Fork 语义

Fork 从来源会话可用的原生上下文生成**独立的新会话**：原会话保留，后续输入互不合并，新联系人可独立命名和操作。

- 优先采用后端官方 Fork 命令或接口。
- 首版可以只支持后端可用的最新分叉点，不要求任意历史消息节点。
- 只有取得有效来源原生 ID，并确认后端支持时，才允许原生 Fork。
- 后端不支持原生 Fork 时，禁用该操作并解释；若以后提供摘要新建，应使用不同名称。
- Fork 过程失败应显示错误，不能把一个没有继承上下文的空会话标为成功。
- 创建分支卡片可以先处于“待启动分叉”；原生命令启动、身份确认之前，不显示为分叉已完成，也不能继续从该卡片分叉。
- 新会话原生 ID 可以在启动后确定；等待期间保存的来源 ID 只用于原生 Fork 命令，不能当作新分支的身份。

**会话 Fork 不会自动创建 Git 分支或 worktree。** Claude、Codex 的 Fork 窗口允许填写已有的目标工作目录；dsh 原生 Fork 保留原目录，当前不支持改目录。群组内“从已有联系人 Fork”默认沿用来源目录；需要为 Claude/Codex 指定目录时，可从来源卡片打开 Fork 窗口并选择目标群组。

## 8. 基础群组

### 8.1 群组与成员

群组具有名称、共同目标、成员联系人和持久化消息记录。成员仍是完整会话联系人，具有同样的状态、改名、进入和原生交互能力。

两种加入方式：

1. **在群组中新建**：选择后端，创建归属该群组的新会话。
2. **从已有会话 Fork 入群**：保留原联系人，新分支归属目标群组并记录来源。

“移入群组（Fork）”在本产品中的含义是第二种，不是直接移动原会话，也不是让内外两张卡片控制同一个上下文。群组成员可以再次单独打开，用户纠正后继续参与共同任务。

### 8.2 本轮必须完成的协作闭环

- 展示共同目标与成员状态。
- 用户在群组记录消息、任务说明与结果。
- 明确选择一个或多个成员，为其准备任务或共享消息。
- Codex 图形模式：通过原生接口直接发送，记录为「已发送」；切换到终端模式后，与 Claude 一样先填入终端，用户检查后按回车提交。dsh 通过原生会话接口发送。图形模式执行中或有待回复请求时，不插入新一轮任务。
- 记录收件人及“待处理 / 投递中 / 结果待确认 / 已填入 / 已发送 / 已取消”状态。先持久化投递尝试，再调用原生接口；连接中断、响应丢失或投递中重启会转为“结果待确认”，禁止直接重发。进入原生会话核对后，可确认已收到、确认未收到并恢复待投递，或关闭投递。只有明确未被原生接口接收的请求才能直接恢复待处理。已填入终端不等于 Agent 已收到。
- 能将一个成员的结果显式共享到群组，再交给其他成员继续处理。
- 群组消息可直接“转交为任务”：预填可编辑内容、指定接收人并保留来源链接。创建后仍为待投递；已有草稿须由用户选择保留或替换，转交来源随草稿保存。
- 服务端每页最多返回 200 条群消息及该页的投递摘要；进入群组读取最新页，后续按变更游标增量同步，可逐页读取更早记录。已加载的来源消息直接定位，未加载的来源按消息 ID 单独读取并弹窗展示。展开历史保留阅读位置和草稿，中文输入法选词时不会误触发布快捷键。
- 能在群组内整理最终结果；结果保留成员或消息来源。
- 单独进入成员纠正时，输入仅送达该成员；涉及其他成员的变更由用户显式同步。

首版采用**用户主导的路由**。群消息不默认广播，不让成员自动回复所有消息；自动分工、管理员 Agent、循环对话和自动冲突处理后置。基础群组已经能协作，但不承诺全自动编排。

## 10. 数据与技术方案

首版采用 Node.js 24、TypeScript、React、Vite、xterm.js、node-pty 与 Node 内置 SQLite。浏览器通过本地 HTTP API 和实时连接访问服务，终端输出与状态同步到页面；dsh 由独立适配器连接原生 Web 服务。

主要实体：

| 实体 | 关键数据 |
|---|---|
| Session | 本工具 ID、后端、名称、工作目录、原生 ID、状态及依据、群组归属、Fork 来源、时间、归档标记 |
| Group | ID、名称、共同目标、创建与更新时间 |
| GroupMessage / Delivery | 群组、正文、类型、来源成员、收件人、填入或发送结果、时间 |
| Event | 会话或群组、类型、必要载荷、时间 |

元数据持久化到 SQLite；终端通过 xterm 状态序列化保存最近 1000 行滚动历史，最多保留 10 个已结束会话的内存画面，重连恢复光标和原生屏幕状态。这些终端快照不会写入磁盘，服务重启后原生历史仍由后端负责。不要默认存储密码或解析用户的认证凭据。真实会话数据与演示数据明确区分。

### 本地运行

环境要求：Node.js 24；使用真实后端时需要分别安装并完成 Claude Code、Codex、dsh 的原生登录。`node-pty` 在没有适用预编译包时需要系统原生编译工具。

已在 Linux（前轮）和 macOS（本轮）运行本地回归；CI 配置覆盖 Node.js 24 的 Linux/macOS 构建、后端与 Chromium 检查。Windows 尚未验收；按 PID 启动时间核对并回收多代进程的增强逻辑目前仅用于 Linux。安装与启动时修复 macOS node-pty helper 的执行权限，启动预检会实际创建一个短生命周期 PTY。

一键启动：

```sh
./start.sh
```

脚本检查 Node.js 24+ 和 npm，在缺少依赖或依赖清单更新时自动安装，然后构建并启动。浏览器访问 `http://127.0.0.1:4317`，终端按 Ctrl+C 正常关闭。可以从其他目录通过脚本的绝对路径启动；工作目录统一为项目目录。

默认只监听本机。如需让局域网设备访问，指定监听所有网卡：

```sh
SESSIONDECK_HOST=0.0.0.0 ./start.sh
```

然后从其他设备打开 `http://服务器局域网IP:4317`。监听 `0.0.0.0` 或 `::` 时，服务接受任意主机名或 IP 的同源访问，无需配置允许列表。开发模式在命令末尾加 `--dev`。

开发模式使用 `./start.sh --dev`，查看选项使用 `./start.sh --help`。沿用下方环境变量，例如 `SESSIONDECK_PORT=4327 ./start.sh`；设置数据目录时建议使用绝对路径。同一数据目录已有实例运行时，需先关闭该实例。

开发模式若提示 `ENOSPC: System limit for number of file watchers reached`，可使用 `CHOKIDAR_USEPOLLING=1 ./start.sh --dev` 改为轮询文件变化；默认启动不需要文件监听。

手动安装和开发启动：

```sh
npm install
npm run doctor
npm run dev
```

浏览器访问 `http://127.0.0.1:4317`。生产构建与运行：

```sh
npm run build
npm start
```

```sh
npm test
npm run verify
```

`doctor` 检查 Node、PTY、目录权限与原生命令，不检查登录凭据或调用模型；`verify` 依次构建、运行后端测试和浏览器验收。

浏览器验收使用隔离的演示数据，首次需要安装 Chromium。先完成生产构建，再执行：

```sh
npx playwright install chromium
npm run test:web
```

可选原生启动检查使用临时配置和工作目录，不输入提示词，不执行模型任务：

```sh
npm exec tsx scripts/native-cli-smoke.ts
```

真实原生程序的隔离工作流验收使用确定性的本机模型服务，不消耗模型额度。dsh 使用独立配置与外网连接拦截；Claude 与 Codex 使用独立配置及 Linux 网络命名空间，因此需要 `unshare` 和可用的用户命名空间：

```sh
npm run test:smoke:dsh
npm run test:smoke:codex
npm run test:smoke:claude
npm run test:smoke:workspace
```

`test:smoke:workspace` 通过真实 HTTP / WebSocket 服务连接三个原生程序，验证建群、定向任务、原生确认执行、结果转交、Fork 入群、单独纠正，以及服务重启后的元数据和原生 ID 恢复。它同样使用临时配置及仅有 loopback 的网络命名空间；无需真实账号或 API Key。该检查验证本地接入链路，不代表真实云端模型质量或账号环境。

Codex 图形交互另有真实 CLI 的本地协议验收：

```sh
npm run test:smoke:codex-chat
```

该脚本使用临时 `CODEX_HOME`、精简环境和仅指向随机本机端口的模拟 Responses 服务，不读取真实凭据，也不请求真实模型。它验证图形发送、流式事件、请求去重、原生审批拒绝、Fork 独立、中断及同一线程的终端连接；不依赖 `unshare`，不提供网络命名空间隔离，也不代表真实账号或云端任务质量验收。

可重复的长时间稳定性检查使用临时演示数据、三个真实 PTY 及循环重连／投递／停止恢复，将报告保存至 `artifacts/`：

```sh
npm run test:soak -- --minutes=45
npm run test:terminal-load -- --minutes=10
```

默认应用数据目录：`~/.local/share/sessiondeck`，可通过 `SESSIONDECK_DATA_DIR` 指定。数据目录使用独立 `instance-lock.sqlite` 的独占事务锁，支持长路径及目录别名，进程退出或被杀后由操作系统释放；不要删除正在使用的锁文件。升级本次锁机制变更时，应先正常停止旧版服务再启动新版。演示模式用于验证界面与组织流程，不能证明真实后端接入成功；使用独立目录启动：

```sh
SESSIONDECK_DEMO=1 SESSIONDECK_DATA_DIR=/tmp/sessiondeck-demo npm run dev
```

可选设置：

| 变量 | 默认值与作用 |
|---|---|
| `SESSIONDECK_PORT` | `4317`，Web 应用端口（也接受 `PORT`） |
| `SESSIONDECK_HOST` | `127.0.0.1`，Web 监听地址（也接受 `HOST`）；设置为 `0.0.0.0` 或 `::` 可接受局域网访问 |
| `SESSIONDECK_DATA_DIR` | 本地元数据目录，同一目录只允许一个服务实例 |
| `SESSIONDECK_DSH_PORT` | `4318`，按需启动的 dsh 原生 Web 服务 |
| `SESSIONDECK_CODEX_PORT` | `4319`，按需启动的 Codex app-server；`0` 自动选择空闲端口 |
| `SESSIONDECK_CLAUDE_BIN` / `SESSIONDECK_CODEX_BIN` / `SESSIONDECK_DSH_BIN` | 可选原生程序绝对路径，未设置则从 `PATH` 查找 |

Codex app-server 只监听本机并使用随机访问令牌。令牌文件仅当前用户可读，正常关闭后删除；令牌不会发送给网页或出现在命令参数中。

元数据可在线备份，不用停止正在运行的会话：

```sh
npm run backup
npm run backup -- --output /path/to/new-backup.sqlite
```

默认写入当前数据目录的 `backups/`；备份包含联系人、群组、群消息、投递记录和活动，**不包含三种原生工具自己的历史或凭据**。命令使用 SQLite 一致性备份，不会改变运行状态，现有目标文件不会被覆盖。

恢复时先停止 SessionDeck，把备份文件放入一个新的空目录并命名为 `sessiondeck.sqlite`，再用 `SESSIONDECK_DATA_DIR=/path/to/restored npm start` 启动；这样保留现有数据目录供回退。原生会话仍需原有原生历史及可用的工作目录。服务恢复后所有托管进程均显示未运行，不会自动重新执行任务。

运行命令与能力边界需随实现同步维护。真实后端的登录、额度和平台可用性由本地环境决定。

## 11. 本地边界

- 服务默认只监听 `127.0.0.1`，首版面向本机单用户浏览器。
- 本工具不默认上传会话或启用云同步；原生 Agent 仍按其配置连接各自服务。
- 浏览器写操作和终端连接需校验来源，防止任意网站控制本地会话。
- 本地开发、测试和提交不授权创建、删除、推送或修改任何云端仓库；具体云端操作必须另获明确授权。
- 不默认替后端批准操作，不通过关闭安全确认换取自动化。
- 远程暴露、多用户认证与权限管理不在首版范围。

## 14. 日常使用与恢复

**先创建一张联系人卡片。** 选择后端、名称，点击「浏览」选择已有工作目录，或粘贴路径／`file://` 链接，进入后启动原生会话。卡片显示最近输入，目录旁按钮可直接复制完整路径。Codex 默认打开「图形对话」，直接输入发送，回复支持 Markdown 和代码复制，审批及提问出现在对话中；随时可切换「原生终端」。Claude 在页面终端使用，也可切换只读记录；dsh 使用内嵌原生界面。首次登录或图形界面尚不支持的确认在原生终端处理。关闭详情只离开视图；Codex「停止生成」中断当前一轮，「停止会话」结束托管运行。

**让几个会话协作。** 创建群组并写下共同目标，添加新成员或 Fork 已有会话。写一条任务，选择收件人，再处理每个成员的待投递项。Codex 图形成员和 dsh 的“发送到会话”通过原生接口执行；Claude 与 Codex 终端成员的“填入”只准备输入，需要进入该成员按回车。群内没有自动广播。

**共享结果并继续。** 在成员私聊中选中需要的输出，作为结果共享到群组；也可直接填写结果并标注来源成员。使用“转交为任务”修改说明、指定下一位成员，再确认投递。卡片仍可随时单独打开纠正；Fork 的会话上下文独立，但工作文件默认共享。

**处理连接问题。** 卡片状态代表 Agent 的执行状态，终端“已连接”只代表浏览器通道可用。浏览器断线后会自动恢复；服务重启后，卡片保留，但原生进程需要手动恢复。使用 `npm run doctor` 检查本地环境，进入“连接与能力”重新检测原生命令。端口冲突时设置对应的端口变量，不会接管或停止占用端口的其他服务。

**遇到请求超时。** 启动、停止或 Fork 需要等待原生程序响应，页面会保留更长的等待时间。若仍提示超时，先刷新状态并查看是否已经完成，再决定重试。投递显示“结果待确认”时，进入原生会话核对，再选择已收到或未收到；不要重复提交尚未核对的任务。

**保存数据。** 联系人名称、群组和投递记录保存在本机 SQLite；使用 `npm run backup` 生成一致性备份。后端自身的对话历史仍保存在各原生工具中。群组草稿保存在当前浏览器；Codex 私聊草稿和待确认标识保存在当前标签页，均不包含在服务器数据库备份里。
